# The Founder-Gated Model

*The authority structure over the work cycle. The Rush-Player Loop governs tempo; this model governs who decides.*

## The seats

- **Founder** — Supplies vision, quality standard, priority, final judgment, adoption authority. Receives visible results and real tradeoffs — never raw logs or settled questions.
- **Context Holder** — Preserves the thread across all lanes: intent, dependencies, open questions. Coordinates; cannot silently change founder authority.
- **Builders** — Execute bounded assignments in parallel. Return artifact, evidence, known limits, next step. Never issue the final verdict on their own work.
- **Evaluators** — Independently test output against frozen standards. Own the fixtures and the refusal evidence. Must not bend a standard to produce a pass.
- **Auditor** — Verifies the process itself: did every named test actually run? Was the reference frozen first? Does the claim match the evidence? Did any seat grade its own work?

## The cycle

Founder sets the target → context holder routes the work → agents work behind the curtain → evidence is compressed upward → independent verification runs → **founder grades the outcome** → the system learns from the verdict → next objective.

**Silence about process, loud about results.** Do not make the founder watch the work. Make the work visible when it matters.

## The founder's verdict vocabulary

**ACCEPT · REFUSE · REDIRECT · REQUEST VARIANTS · RAISE THE GATE · RECYCLE**

No proposal, consensus, ranking, or automated score overrides the founder's ruling.

## The escalation test

Interrupt the founder only when at least one is true:

1. The objective is genuinely ambiguous.
2. Two valid paths create different products.
3. Identity or visual direction is at stake.
4. The acceptance gate must change.
5. A security or authority boundary is implicated.
6. Evidence contradicts a founder ruling.
7. The next action is irreversible.
8. Progress is blocked with no useful parallel work remaining.

Otherwise, continue working.

## Verdict learning

After every verdict: corrections become tests · failures become fixtures · accepted methods become infrastructure · visual judgments become grading criteria · the baseline updates. The founder should never have to give the same correction twice.

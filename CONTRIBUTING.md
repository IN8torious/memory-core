# Contributing — forks welcome, proposals gated

This repository is public in the spirit of shared research: the way research teams share data and arrive at unified conclusions. Two different doors are open, and they work differently.

## Door one: fork it — free, no permission needed

**Anyone may fork this repository and adapt the structure for their own memory core.** That is the point of publishing it. Take the shape — a public core over a private full record, doctrine as files, receipts as the standard of truth — and build your own. Attribution to N8toriousAi is appreciated; permission is not required.

Forks are independent. What you build on the pattern is yours.

## Door two: contribute back — pull requests are proposals

Changes to *this* core come in as **pull requests, and a pull request is a proposal** — nothing more, nothing less.

This mirrors the house's own authority model ([doctrine/founder-gated-model.md](doctrine/founder-gated-model.md)): work is delegated, judgment is not. The founder reviews each proposal and answers with one of:

- **ACCEPT** — merged into the core.
- **REFUSE** — not merged, with the reason on the record.
- **REDIRECT** — the idea is sound, the form is wrong; reshape it and return.

A refusal is a valid result, not a personal judgment. The core is one person's working record; its coherence is the founder's call.

## Welcome contributions

- **Adapters and hooking guides** for other AI platforms — how to connect a model, a client, or a local stack to a memory core like this one.
- **Translations of the doctrine** into other agent frameworks, languages, or operating styles.
- **Worked examples** — memory cores built on this pattern, written up so others can learn from the attempt (successes and failures both).
- **Corrections with receipts** — if a fact in this repo is wrong, a correction that carries its evidence is the most valuable contribution there is.

## Never welcome

- **Personal data — of anyone, ever.** This repo is sanitized by law: doctrine, method, project records, and ideas only. No personal details about the founder or any other person belong here, in any file, in any pull request, under any framing. A PR containing personal data will be refused on that ground alone. See the sanitization rule stated in [HOOKING.md](HOOKING.md).

## Style for proposals

Match the house standard: plain words, caption-length where possible, claims carrying their evidence. If your proposal asserts a fact, show the receipt. If it proposes a method, show a worked instance.

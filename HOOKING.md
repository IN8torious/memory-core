# HOOKING.md — connecting an AI to this memory core

Practical instructions for pointing an AI — hosted, desktop, or local — at this repository so it can work from the record instead of starting cold.

## The first instruction to give a fresh AI

Copy this, verbatim, as the opening instruction in a new session:

> **Read the README.md of this repository, then AGENTS.md, then the doctrine index — then work from the record.**

That one instruction is the whole onboarding. Everything else follows from the files.

## Ways to connect

### Paste the repo (simplest, works anywhere)

Give the AI the repository URL, or the raw URL of individual files, directly in chat:

- Repository: `https://github.com/IN8torious/memory-core`
- Any file's raw form: `https://raw.githubusercontent.com/IN8torious/memory-core/main/<path>` — e.g. `.../main/AGENTS.md`

Works with ChatGPT, Claude, DeepSeek, Gemini, and any other chat AI that can fetch a link. Start with README.md and AGENTS.md; pull doctrine or project files as the work requires.

### Clone it (local models and agent stacks)

```bash
git clone https://github.com/IN8torious/memory-core.git
```

A local model or agent framework with file access can read the clone directly — no network dependency, no account, no meter running. This is the sovereign route: the record on your own disk, readable by any mind you run.

### GitHub MCP (read/write agents)

Agents that speak the Model Context Protocol can connect through GitHub's official MCP server and read the repo as structured data — and, where the founder grants it, write back. This is the two-way route: an AI that not only reads the record but files its own receipts into its own fork or branch, as proposals.

## Suggested read order for a working session

1. `README.md` — the letter, the standing rule.
2. `AGENTS.md` — how to work with the founder.
3. `doctrine/README.md` — the index of laws; read the ones your task touches.
4. The relevant file under `projects/` — the line of work you're joining.
5. `ideas/` — when the task is design or direction, not execution.

## The honesty note

**This is the public core. The full memory is private by design.**

What lives here is doctrine, method, project records at the level already public, collaboration preferences, and ideas. The complete record — daily notes, personal context, the unfiltered history — is not in this repo and is not missing by accident. Do not treat the public core as the whole person, and do not ask it to be. It is the part of the record that was built to be shared: enough for any AI to work with the founder well, and no more than that.

## The sanitization law (why the boundary sits where it does)

This repository follows a strict rule, and forks are urged to adopt it:

> **A public memory core carries doctrine, method, project records, and ideas — never personal data. Not the founder's, not anyone's.**

The boundary is what makes the sharing possible. A record that is safe to share gets shared; a record that isn't, doesn't — and then nothing is shared at all. Keep the line bright, and the core can stay public forever.
